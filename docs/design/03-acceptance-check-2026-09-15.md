# 受け入れ確認 2026-09-15

3 人の実装担当が並列で作った直後の版を、画面と API から通しで確認した記録。対象は
`docs/design/01-architecture.md` §7（画面）と `docs/requirements/01-needs-and-requirements-draft.md`
§3（要件）。**コードの修正はしていない**（本文書は確認結果のみ）。

## 結論

**使い始められる状態。** 記録の作成・編集・履歴・画像添付・検索・書き出し・復習（間隔反復）の
一連の流れは、手入力と curl 経由の音声文字起こしの両方で最後まで動いた。見つかった問題はいずれも
「使えない」ものではなく、「気づきにくい不便」または「見た目の軽微な崩れ」にとどまる。ただし
下記のバッジ表示の食い違い（問題 2）は毎日使う画面の数字が信用できなくなる種類の不具合なので、
早めの修正を勧める。

## 問題一覧

### 問題 1：添付・書き出し・スナップショットの時刻が `MNEMORIZE_FAKE_NOW` を無視する（不便）

- **再現手順**：`MNEMORIZE_FAKE_NOW` を実時刻と異なる値にしてサーバーを起動 →
  `POST /api/entries/:id/attachments` で画像を添付する。
- **期待**：返る `created_at` は `MNEMORIZE_FAKE_NOW` に従った時刻になる（`server/adapters/clock.ts` の
  `now()` を通す、というプロジェクトの規約どおり）。
- **実際**：実際のシステム時刻が使われる。同じ問題が JSON 書き出しの `exported_at` と、
  スナップショットのファイル名（`mnemorize-YYYYMMDD-HHMM.sqlite`）にもある。
- **原因箇所**：`server/routes/attachments.ts` が `addAttachment(entryId, file)` を
  `now` 引数なしで呼んでいる（`server/services/attachments.ts:25` の既定値
  `now: Date = new Date()` がそのまま使われる）。`server/routes/export.ts` の
  `exportJson()` / `exportMarkdown()` / `createSnapshot()` の呼び出しも同様に引数なし。
- **影響**：通常運用（`MNEMORIZE_FAKE_NOW` 未設定）では実時刻＝本来の時刻なので気づきにくいが、
  日付境界をまたぐ検証や、将来 Tauri 化してタイムゾーンをまたぐ環境では、添付ファイルの
  保存フォルダ（`attachments/YYYY/MM/`）や書き出し内容の時刻が記録の日付とずれる可能性がある。

### 問題 2：復習タブのバッジが「今日の残り」ではなく「期限超過の全件数」を表示する（不便）

- **再現手順**：設定で 1 日の復習上限を 2 に設定 → 期限超過の記録が 3 件ある状態で
  画面を開く。
- **期待**：バッジは今日中に処理すべき件数（上限適用後の残数）を示し、今日分をすべて
  評価し終えたら 0 になる（繰り越しの有無は復習画面のヘッダーで別途示す）。
- **実際**：バッジは `GET /api/reviews/today` の `total_due`（上限を考慮しない全期限超過数）を
  表示する（`web/src/main.tsx:28`）。今回の確認では、開いた直後はバッジ「3」・復習画面ヘッダーは
  「今日の復習 0/2件・繰り越し1件」と数字が食い違い、2 件を評価し終えてもバッジは「1」のまま
  0 にならなかった（1 件が明日以降に繰り越されているため）。
- **影響**：復習画面のヘッダーは正しいので実害は小さいが、タブのバッジだけを見るユーザーは
  「まだ何件も残っている」と誤解し、実際には今日のノルマを終えているのに気づきにくい。

### 問題 3：画像の原寸表示を Escape キーで閉じられない（見た目・軽微）

- **再現手順**：カードのサムネイルをクリックして原寸表示を開く → Escape キーを押す。
- **期待／実際**：閉じない。画像の外側（暗い余白部分）をクリックすると閉じる。

### 問題 4：一覧カードで段落間の空行が畳まれる（見た目・軽微）

- **再現手順**：本文に空行区切りの複数段落を含む記録を作成し、「今日」画面の一覧カードを見る。
- **期待／実際**：Markdown 書き出しファイルでは段落間の空行が正しく保持されている
  （`export/2026/2026-09-15.md` で確認済み）が、一覧カードの表示では改行 1 つ分に詰まって見える。
  内容の欠落ではなく見た目だけの問題。

## 確認できなかった項目とその理由

- **項目 12 の「文字起こし中…」進行カードの表示**：確認できなかった。指示どおり curl で
  `POST /api/transcriptions` を実行したが、このアプリの実装ではブラウザ自身が録音を開始した
  ときにだけ進行中カードの状態（`jobIds`）を持つため、外部（curl）から作ったジョブを画面が
  検知する経路がない。ブラウザからマイクで録音して確かめる必要があるが、本タスクではマイク
  権限ダイアログが出る操作を避ける指示のため未実施。ジョブ自体は正常に完了し、記録は
  再読み込み後に正しく反映されることは確認済み。
- **項目 14 のライトモード**：確認できなかった。本セッションで使った Chrome には DevTools の
  ライト／ダークエミュレーション機能が使えず、OS のシステム設定（現在ダーク）に依存する。
- **項目 15 の幅 420px 表示**：確認できなかった。`resize_window` ツールでブラウザウィンドウの
  サイズを 420×900 に変更しても、ページの実効ビューポート幅（`window.innerWidth`）が
  1710 のまま変化しなかった。自動化ツール側の制約で、アプリのレイアウトの問題ではない。

## スクリーンショットの保存先
