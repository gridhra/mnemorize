- 作成日：2026-09-15
- 状態：**承認済み（2026-09-15）。画面実装の基準文書。**設計01の §7「画面（案）」はこの文書で置き換える。実装の段階分けと担当は §7と `docs/design/02-implementation-plan.md` を見る。

- 読み手：この文書だけで画面を実装できるように書く。用語は節の中で定義する。

## 0. この文書だけで分かる用語

- **記録**…利用者が1日のうちに残す1件のメモ。音声の文字起こし、手入力、画像で作る。復習の単位でもある。
- **学習日**…午前4時（設定で変更可）を境に切り替わる日付。深夜2時に書いた記録は前日の記録になる。
- **復習**…期限が来た記録を、手がかり（タイトルか本文の先頭1文）だけ見て思い出し、本文を開いて答え合わせし、3段階で自己評価すること。評価から次の期限が決まる（FSRSという間隔反復アルゴリズム）。
- **期限**…その記録を次に復習する日。
- **復習を終えた記録**…もう復習に出さないと決めた記録。日付の一覧には残る。コードではretire（卒業）と呼ぶが、画面ではこの言い方を使わない（§5）。

## 1. 現行の何が問題か（棚卸しの要約）

事実として確認したもの。

1. **「今日」画面が「任意の1日」画面になっている。**前の日・次の日で何日でも移動でき、未来にも進める。「今日」タブを見ているのに別の日を見ている状態が起きる。
2. **ボタンが状態で増減する。**今日以外を見ているときだけ「今日へ」が4つ目として右端に生え、幅が足りないと折り返して見出しがずれる。
3. **過去の日へ行く手段が「前の日」の連打しかない。**カレンダーが無い。記録のある日を返すAPI（`GET /api/days?from=&to=`）は実装済みだが未使用。
4. **復習が別タブに隔離されている。**今日やることは「復習」と「記録」の2つなのに、片方が別画面で、件数バッジも記録を作っただけでは更新されない。
5. **間隔反復の情報が画面に出ない。**サーバーは「何日後か」「何回目か」「忘れた回数」「安定度」「今の想起見込み」「復習の履歴」を返しているが、画面に出るのは次回の日付だけ。
6. **設定画面が内部語のまま。** 「ハルシネーション定型句」「一日の境界時刻」「スナップショット」「Whisperモデルのパス」に説明が無い。自動で復習を終える設定（`auto_retire`）は画面に無いのに既定で有効。
7. **URLが無い。**再読み込みで今日に戻る。戻る・進む・ブックマークが効かない。
8. **視覚の手がかりが薄い。**ホバー無し、フォーカス枠は入力欄だけ、画面幅への調整無し、状態色はエラーの赤だけ。CSS規則の無いクラスが7つ。
9. **未使用・不一致の文言。**使われない文言3件、画面によって説明の有無が違う操作（復習を終える）、確定と予告で同じ文字列（「次回 …」）。

## 2. 設計思想（3つの原則）

すべての画面・文言・見た目の判断は、次の3つに帰着させる。

### 原則A：今日は一枚の紙

このアプリで毎日することは2つだけ。**期限が来た記録を復習する**ことと、**今日やったことを記録する**こと。この2つは「今日」画面に、この順で、上から並ぶ。「今日」画面は今日しか表示しない。別の日を見たくなったら別の画面（カレンダー）へ行く。

生まれた出来事：「今日」タブで別の日を見られる現行の作りに対し、ユーザーが「意味不明」と評した（2026-09-15）。

### 原則B：置き場所は動かない

操作部品（ボタン・リンク・入力欄）は、状態によって現れたり消えたり位置を変えたりしない。使えないときは**無効化**（押せない見た目）にして、その場に残す。数が変わってよいのは一覧の項目（記録カード、検索結果）だけ。

生まれた出来事：「次の日」を連続で押していると、今日を離れた瞬間に「今日へ」が横に生えて、押す位置が変わった（2026-09-15）。

### 原則C：初見で意味が取れる

画面に出る文はすべて、このアプリを初めて開いた人（間隔反復も音声認識も知らない）が一度で意味を取れるように書く。内部の言葉（卒業、繰り越し、境界、スナップショット、ハルシネーション、Whisper、モデル）は画面に出さないか、初出でその場に一句の説明を付ける。設定項目には必ず「これを変えると何が起きるか」を一文添える。日本語の書き方は `docs/writing-guidelines.md`（正書法と検査スクリプト）に従う。

生まれた出来事：設定画面の「ハルシネーション定型句（1行に1句）」に、ユーザーが「なんだよ」と評した（2026-09-15）。

## 3. 画面の構成

画面は4つ。上部の帯に常に4つの入口を同じ順で置く。**入口の並びと数は状態で変えない**（原則B）。

| 入口 | URL | 役割 |
|---|---|---|
| 今日 | `#/today` | 今日の復習と、今日の記録。既定の画面。 |
| カレンダー | `#/calendar/2026-09`、`#/day/2026-09-10` | 過去の日の記録を見る・書き足す。これからの復習予定を見る。 |
| 検索 | `#/search?q=` | 全文検索。 |
| 設定 | `#/settings` | 文字起こし・復習・データの設定。 |

URLはハッシュ（`#/…`）で持つ。再読み込みしても同じ画面に戻り、ブラウザの戻る・進むが効く。ルーターは自前の小さなもの（`hashchange` を監視する60行程度）で足りる。ライブラリは入れない。

上部の帯の左端にアプリ名「mnemorize」を置く（現行は名前がどこにも出ない）。「今日」の入口には、今日まだ評価していない復習の件数を数字で添える。この数字は、復習を1件評価したとき・記録を1件作ったとき・画面を開き直したとき、のいずれでも更新する。

### 3.1今日（`#/today`）

今日しか表示しない。日付の移動は無い。上から：

1. **日付の見出し**…「9月15日（月）」。その右に小さく「深夜3時までは今日として扱います」のような一文は置かない（設定画面で説明する。ここは静かに保つ）。
2. **今日の復習**（節の見出し）
   - 期限が来た記録があるとき：進み具合「2 / 8件」と、上限で明日以降に回した件数があれば「ほかに3件は明日以降に出ます（1日の上限10件）」を平文で（`title` 属性に隠さない）。その下に復習カード1枚（§3.5）。
   - 全部終えたとき：「今日の復習は終わりました。次の復習は9月17日（水）に2件あります。」
   - 最初から0件のとき：「今日の復習はありません。次は9月17日（水）に2件あります。」記録が1件も無い初回だけ「記録を作ると、翌日から復習に出ます。」を添える。
3. **今日の記録**（節の見出し）
   - 新規作成の欄を**一覧の上**に置く（現行は下。今日の主目的は書くことなので、開いてすぐ手が届く位置にする）。録音ボタン・本文欄・画像の受け口をまとめた1枚のカード（§3.4）。
   - その下に今日の記録カードを新しい順。文字起こし中のカードはこの一覧の先頭に出る。

復習と記録の2節は、どちらかが空でも見出しごと残す（原則B）。

### 3.2カレンダー（`#/calendar/YYYY-MM` と `#/day/YYYY-MM-DD`）

「今日以外の日」に関することはすべてここで扱う。過去の記録を読む・書き足す、これからの復習予定を見る、の両方。

**月の画面**（`#/calendar/2026-09`）：

- 見出し「2026年9月」と、左右に「前の月」「次の月」。これらは常に3つ並び、今月を表示中でも「次の月」は消さない（未来の月は復習予定を見る用途がある）。見出しの右に「今月へ」を**常に**置き、今月表示中は無効化する。
- 週は月曜始まり（要件J7）。各日のマスに2つの印：記録の件数（小さな点または数字）と、その日に期限が来る復習の件数。今日のマスは枠で強調。
- マスを押すと日の画面へ。
- 月の下に「これからの復習」の一覧：今日から14日分、日ごとに件数と記録の見出しを畳んで表示。これが「これからの予定」の置き場。

必要なAPI：記録の件数は既存の `GET /api/days?from=&to=`。復習予定は新設 `GET /api/reviews/upcoming?from=&to=`（日ごとの期限件数と記録の見出し）。

**日の画面**（`#/day/2026-09-10`）：

- 見出し「9月10日（木）」。左右に「前の日」「次の日」。見出しの右に「カレンダーへ」（月の画面に戻る）。この4つは常にこの位置。今日の日付を開いたときも同じ画面構成で、「今日」画面には自動で飛ばさない（画面の役割が違う。復習はここではしない）。
- 過去の日：その日の記録の一覧と、末尾に「この日に書き足す」の新規作成欄（書き忘れを翌朝書く用途。要件D2）。
- 未来の日：「この日に復習の期限が来る記録」の一覧（読むだけ）。新規作成欄は出さない。
- 今日の日付：記録の一覧と新規作成欄（今日画面と同じ内容）。上部に「今日の復習は『今日』の画面で」と一文。

検索結果から飛ぶ先もこの画面。`#/day/2026-09-10?entry=<id>` の形で、該当の記録カードを強調して画面内に出す。

### 3.3検索（`#/search`）

現行のままでよい部分が多い。変える点：

- 「2文字でも検索できます」は削る（内部事情）。
- 結果カードに「本文／タイトル／文字起こしの原文」のどれに当たったかを小さく示す（APIは返している）。
- 結果を押すと `#/day/…?entry=…` へ飛び、該当カードを強調。
- 検索語はURLに持ち、戻るで結果に戻れる。

### 3.4記録カードと新規作成の欄

**記録カード**（今日画面・日の画面・検索から共通）。上から：

1. 見出し（タイトル、無ければ本文の先頭1文）
2. **復習の状態を1行**で：「次の復習9月18日（金）・3日後・2回目」。復習を終えた記録は「復習は終了（9月10日に終了）」。復習の対象外は「復習しない記録」。
3. 画像のサムネイル（全部出す。5枚以上は横スクロール。「他N枚」の文字は廃止）
4. 本文。**本文は押しても編集に入らない**（文字を選択できる）。編集は操作ボタンから。
5. 操作ボタンの列。常に同じ4つを同じ順で：「編集」「復習の記録」「本文の履歴」「その他」。
   - 「復習の記録」…いつ・どう評価したかの一覧（`GET /api/reviews/:entry_id/logs`。未使用だったAPI）と、いまの状態：「安定度：およそ12日（この日数は忘れにくさの目安）」「今の想起見込み：87%」「忘れた回数：1回」。
   - 「本文の履歴」…加筆修正の版一覧。各版に「この版に戻す」を付ける（現行は読むだけ）。
   - 「その他」…「画像を追加・削除」「もう復習しない」（確認あり。復習画面と同じ文言・同じ確認文）「復習をもう一度最初から」。

**新規作成の欄**（今日画面、日の画面の過去日）。1枚のカードにまとめる：

1. 一番上に大きな「録音して記録する」ボタン。押すと同じ場所が「停止して文字起こしする」に変わる（同じボタンが状態を変える。別のボタンが生えるのではない。原則B）。右に経過時間と音量。
2. 本文欄（プレースホルダ「今日やったことを書く。あとで思い出せるように、要点を2〜3個」）。タイトル欄は本文の上に細く置き、ラベルは「見出し（省略すると本文の先頭1文を使います。復習のとき最初に見えるのはこの1行です）」。
3. 画像の受け口（ドロップ・貼り付け・ファイル選択）。
4. 右下に「記録する」。左下に「復習に出す」のチェック（既定オン）。

既存の記録に音声で追記する導線（現行は部品だけあって画面に無い）は、記録カードの「編集」の中に「録音して書き足す」として置く。

### 3.5復習カード（今日画面の中）

**開く前**：見出し（手がかり）と「9月10日（木）に記録・画像2枚・2回目の復習」。中央に「思い出せたら開く」。その上に小さく、この画面の趣旨を毎回1行：「本文を見る前に、何の話だったか自分の言葉で言ってみてください。」（初回だけでなく毎回出す。短いので邪魔にならない）。

**開いた後**：本文と画像。「思い出したことを書き足す」欄。評価ボタン3つは常に横1列（狭い画面では縦1列に切り替えるが、途中で2+1に割れる状態は作らない）。各ボタンは3段：

| 段 | 思い出せなかった | 思い出せた | 余裕だった |
|---|---|---|---|
| 基準 | 本文を開く前に、何の話か出てこなかった | 本文を開く前に、要点を2〜3個言えた | 本文を開く前に、ほぼ全部説明できた |
| 次回 | 明日（1日後） | 9月22日（火）・6日後 | 12月3日（木）・79日後 |

「余裕だった」の説明から「次は数か月〜1年先になります」を外す（次回の段に日数が出るので重複）。

評価後：「次の復習は9月22日（火）、6日後です。」と「取り消す」。取り消したらキューを取り直す（現行は古い予告のまま）。最長の間隔に達して自動で復習を終えたときは「間隔が1年に達したので、この記録の復習を終えました。カレンダーからいつでも読めます。」

「もう復習しない」はカードの最下部に、開く前・開いた後とも同じ位置。

### 3.6設定（`#/settings`）

3つの節に分け、各項目に「ラベル」「一文の説明（これを変えると何が起きるか）」「入力欄」の3点を必ず揃える。

**音声の文字起こし**

- 状態（読むだけ）：「文字起こしの準備：できています／音声認識のプログラム（whisper-cli）が見つかりません／モデルファイルが未設定です」。できていないときは「録音はできますが、文字起こしは動きません。」と、設定の手順（Homebrewでの導入コマンドとモデルの入手先）を3行で。
- モデルファイルの場所…「音声認識に使うモデルファイル（拡張子.bin）の場所です。」
- 覚えさせたい言葉…「よく話す専門用語や固有名詞を1行に1つ。文字起こしがその表記を使いやすくなります。」
- 無音のときに出やすい誤認識…「音声認識は無音の部分で決まり文句（例：ご視聴ありがとうございました）を勝手に出すことがあります。ここに書いた句と一致する部分は取り除きます。1行に1句。」

**復習**

- 1日に出す復習の上限…「期限が来た記録がこの件数を超えた日は、超えた分を翌日以降に回します。」単位「件」を付ける。
- 間隔が1年に達したら復習を終える…チェック（`auto_retire`。現行は画面に無い）。「オフにすると、1年ごとに復習が続きます。」
- 日付の切り替え時刻…「この時刻より前は前日として扱います。深夜に書いた記録が前日の記録になり、復習の期限もこの時刻に切り替わります。」

**データ**

- データの置き場（読むだけ）：フォルダのパス。「このフォルダをまるごと複製すれば、すべての記録の控えになります。」
- 書き出し：「Markdownで書き出す」「JSONで書き出す」。結果は「書き出しました：<パス>（12ファイル）」と、Finderで開くボタン（サーバーに `open` を頼む小さなAPIを足す。ローカル前提なので許容）。
- 控えを作る（現行「スナップショット」）：「データベースの複製を1つ作ります。」＋控えのコピー先（任意）「同期フォルダなどを指定すると、そこにもコピーします。」

値の検証：範囲外の値は黙って直さず、その場に赤字で「1〜200の範囲で指定してください」と出す。サーバーのエラー文から内部キー名（`（daily_review_limit）`）を取り除く。「保存しました」は3秒で消す。

## 4. 間隔反復の情報をどう見せるか

方針：**数字は日数と回数で、確率は百分率で、内部の名前（stability、difficulty、retrievability、reps、lapses）は出さない。**

| 内部の値 | 画面での言い方 | 出す場所 |
|---|---|---|
| due | 「次の復習9月18日（金）・3日後」 | 記録カード、復習の予告 |
| interval_days | 「・3日後」（上と同じ行） | 同上 |
| reps | 「2回目」 | 記録カード、復習カードの手がかり行 |
| lapses | 「忘れた回数：1回」 | 「復習の記録」の中 |
| stability | 「安定度：およそ12日」＋一句「この日数は、忘れにくさの目安です」 | 「復習の記録」の中 |
| retrievability | 「今の想起見込み：87%」 | 「復習の記録」の中 |
| review logs | 「9月10日 思い出せた → 次回9月16日」の一覧 | 「復習の記録」の中 |
| total_due / carried_over | 「ほかに3件は明日以降に出ます（1日の上限10件）」 | 今日画面の復習の節 |
| 次に期限が来る日 | 「次の復習は9月17日（水）に2件」 | 今日画面（復習が0件・終了時）、カレンダー |

「今日の復習2 / 8件」の分母は上限で切った後の件数のままとし、切った分は上の一文で示す（分母を総数にすると、上限で回した分が「今日やり残した」ように見える）。

## 5. 文言の規範（画面に出る言葉）

`docs/writing-guidelines.md` に規則として置く。要点：

1. 内部語の置き換え表（画面ではこちらだけを使う）：

| 内部の言葉 | 画面の言葉 |
|---|---|
| 卒業（retire） | もう復習しない／復習は終了 |
| 繰り越し | 明日以降に出るN件 |
| 一日の境界時刻 | 日付の切り替え時刻 |
| スナップショット | 控え（データベースの複製） |
| ハルシネーション定型句 | 無音のときに出やすい誤認識 |
| Whisperモデルのパス／モデルファイル | モデルファイルの場所（音声認識に使う） |
| 専門用語リスト | 覚えさせたい言葉 |
| 手がかり | 見出し（復習のとき最初に見える1行） |
| 文字起こし原文 | 文字起こしのまま（編集前）の文 |
| 送っています… | 文字起こしの準備をしています… |

2. 同じ操作は、どの画面でも同じ文言・同じ確認文。
3. 確定と予告を同じ文字列にしない（「次の復習 …」は確定、「次回 …」は予告）。
4. 説明は `title` 属性に隠さない。平文で置く。
5. 正書法（和文と半角英数の間は詰める、機能する記号は全角）。検査は `bun run check:text`。

## 6. 視覚の規範

- **トークン**：色8個に加え、状態色を3つ足す（`--ok` 緑、`--warn` 黄土、`--danger` 既存の赤茶）。間隔は4px刻み（`--sp-1`〜`--sp-6`）。
- **押せるものの見た目**：ボタン・タブ・カードの操作にはホバー（面が1段濃くなる）とフォーカス枠（2pxのアクセント色、`:focus-visible`）を必ず付ける。
- **主操作は画面に1つ**：塗りつぶしのボタンは、今日画面では「録音して記録する」、復習カードでは「思い出せたら開く」、設定では「保存」だけ。ほかは枠線のボタン。
- **画面幅**：640px未満で、評価ボタン3つを縦1列に、カレンダーのマスを小さく、上部の帯を2段に。それ以外の幅では横並び。中間で2+1に割れる配置を作らない。
- **状態で消さない**：無効化は `opacity` ではなく、文字色を `--muted`、枠を `--line` にして、カーソルは既定のまま。復習を終えた記録カードも全体を薄くせず、状態の1行で示す。
- **ダークモード**：OS追従のまま（アプリ内の切り替えは作らない。個人用ローカルアプリのため）。
- **CSS規則の無いクラス**を無くす（棚卸しで7つ）。

## 8. していないこと・決めていないこと

- 復習を「今日」画面に置いたことで「復習」タブは無くなる。復習だけを集中してやる画面が欲しくなったら、今日画面の復習の節を全画面にする「集中モード」を足す（今回は作らない）。
- 「これからの復習」を14日分としたのは仮の値。月の画面で未来の日を押せば任意の日の予定は見られる。
- Safariでの確認は引き続きしていない。
- 画面幅640pxの閾値は、評価ボタン3つ（各10em）と余白から逆算した仮の値で、実機で調整する。
