# 設計06：デザインシステム（部品と見た目の規範）

- 作成日：2026-09-15
- 状態：**画面の部品と見た目の基準文書。**`web/src/styles.css` の部品とパターンの並びは、この文書の§4・§5と同じ順にしてある。
- 読み手：この文書だけで部品を新しく作れる・変えられるように書く。用語は各節の中で定義する。

## 1. 目的と適用範囲

**この文書は何か。**mnemorizeの画面に出る部品（ボタン、カード、入力欄など）の見た目と振る舞いの規範である。
色・間隔・字の大きさといった値の一覧（**デザイントークン**＝`styles.css` の `:root` に置いたCSS変数。
「値に名前を付けて、直書きを禁じる仕組み」のこと）、部品ごとの状態と配置の規則、アクセシビリティ、
文の書き方、部品を足すときの手順を含む。

**どこまでを決めるか。**「この部品はどう見えるか」「どの状態を持つか」「どこに置くか」を決める。
「どの画面に何を並べるか」は決めない——それは `docs/design/05-ui-grand-design.md`（以下「05文書」）の仕事である。

| 文書 | 決めること | 例 |
|---|---|---|
| 05文書 | 画面の構成、ナビゲーション、文言の置き換え表 | 「今日」画面は復習の節と記録の節をこの順で並べる |
| この文書（06） | 部品の見た目・状態・配置、トークン、確認手順 | ボタンは既定が枠線で、塗りつぶしは画面に1つだけ |

**この文書が守る対象**は `web/src/styles.css` 1ファイルと、そこにクラス名を書く `web/src/**/*.tsx` である。
インラインスタイル（`style=` 属性）は原則として使わない（§8の禁止事項）。

**生まれた出来事**：2026-09-15の画面の棚卸しで、CSS規則の無いクラスが7つ、同じ「小さい字」が5通りの
大きさ（`0.7rem` から `0.8rem` まで）で書かれていた。値に名前が無いまま増えたのが原因なので、
値に名前を付ける文書を分けて立てた。

## 2. 原則

05文書 §2の3原則（今日は一枚の紙／置き場所は動かない／初見で意味が取れる）を、見た目の判断に落とす。
判断に迷ったら、下のどれかに帰着させる。

### 原則A（継承）：今日は一枚の紙

1つの画面は1枚の紙に見える。面（白いカード）の中にさらに面を重ねない。影は使わない
（§3の「影」を見よ）。奥行きは、地（`--bg`）・面（`--surface`）・罫線（`--line`）の3つだけで表す。

**生まれた出来事**：現行の「今日」画面は復習と記録が別タブに分かれていて、今日やることが一目で
見渡せなかった（2026-09-15の棚卸し）。

### 原則B（継承）：置き場所は動かない

操作部品（ボタン・リンク・入力欄）は、状態によって現れたり消えたり位置を変えたりしない。
使えないときは**無効化**（押せない見た目にして、その場に残す）。色は変えてよい——塗りつぶしを
付け替えても位置は動かないので、この原則には触れない。

**生まれた出来事**：「次の日」を連続で押していると、今日を離れた瞬間に「今日へ」ボタンが横に生えて、
押す位置が変わった（2026-09-15）。

### 原則C（継承）：初見で意味が取れる

説明は平文で画面に置く。`title` 属性（マウスを乗せたときだけ出る吹き出し）に隠さない。

**生まれた出来事**：「上限で明日以降に回した件数」の説明が `title` 属性の中にあり、
マウスを乗せない限り読めなかった（2026-09-15の棚卸し）。

### 原則D：静かな既定

装飾より可読性を優先する。日本語の長い文が読めることが第一（要件J8）。行間は`1.7`、本文は16px、
本文の幅は`42em`で止める。色数を増やさない——使ってよい色は§3の表にあるものだけ。

**生まれた出来事**：日本語の本文が読みやすいことを最初の要件（J8）に置いたのは、このアプリが
「あとで思い出すために自分が書いた文を読み返す」道具だからである。

### 原則E：状態は色でなく言葉で、色は補助

「準備ができている／できていない」「今日の分は終わった」といった状態は、必ず**言葉**で書く。
色（緑・黄土・赤茶）は、言葉に添える補助でしかない。色だけで意味を持たせた部品を作らない。

**生まれた出来事**：文字起こしの準備の状態を出す箱（`.status-box`）は、左の帯を緑か黄土に
塗り分けるが、同時に「文字起こしの準備：できています」という文も必ず出す。色が見えない人にも
同じ情報が届くようにするため。

### 原則F：主操作は1つ

塗りつぶしのボタン（`.button.primary`）は、その画面で「いま次にすべきこと」1つだけに付ける。
ほかはすべて枠線のボタン。どれを選んでも正しい選択肢（復習の評価3段階）には、どれにも付けない
——1つを塗ると「これを選べ」と読めてしまう。

**生まれた出来事**：05文書 §6で、復習カードの評価3ボタンについて「どれも等しく正しい答えなので
塗りつぶしはどれにも付けない」と決めた（2026-09-15）。

### 原則G：破壊的操作は距離と確認で守る

元に戻せない操作（記録そのものの削除）は、（1）ほかの操作から区切り線で離し、（2）赤茶の枠線
（`.button.danger`。塗りつぶしにはしない）で見分けられるようにし、（3）押したときに確認を出し、
確認文に「元に戻せません」と書く。

**生まれた出来事**：「もう復習しない」（記録は残る）しか出口が無く、試し書きした記録が日付の
一覧に残り続けた。記録そのものを消す操作を足したので、2つの区別が読み取れる必要が出た（2026-09-15）。

## 3. デザイントークン

**デザイントークンとは**、色や間隔のような値に名前を付けて `styles.css` の `:root` に1か所だけ
書いたもの（CSS変数）。部品の側では値を直書きせず、この名前だけを使う。値を直したいときに
1か所で済み、「この灰色はどの灰色か」を数えなくて済む。

以下の変数名はすべて `web/src/styles.css` に実在する。

### 3.1色

暗い配色はOS追従（`prefers-color-scheme`）のみ。アプリ内の切り替えは作らない（個人用のローカルアプリのため）。

| 変数 | 役割 | 明るい配色 | 暗い配色 |
|---|---|---|---|
| `--bg` | 地。画面全体 | `#fbfaf8` | `#17181a` |
| `--surface` | 面。カード・入力欄・ボタン | `#ffffff` | `#1f2124` |
| `--surface-sunken` | 面より一段沈んだ面（パスの表示） | `--text`を6%混ぜた面 | 同左 |
| `--text` | 本文 | `#1c1b19` | `#e8e6e3` |
| `--muted` | 補足の文字、無効の文字 | `#6b6862` | `#9b9790` |
| `--line` | 罫線・区切り。飾りであって押せない境目 | `#e2ded7` | `#34373b` |
| `--line-strong` | 押せるものの枠（ボタン・入力欄・マス） | `#8a857d` | `#767a80` |
| `--accent` | 主操作・現在地・フォーカス | `#3b6ea5` | `#7aa7d6` |
| `--accent-text` | アクセント面の上に載る文字 | `#ffffff` | `#11202e` |
| `--accent-hover` | アクセント面に触れたとき | `--accent`を85%に暗く | 同左 |
| `--hover-surface` | 押せるものに触れたときの面 | `--accent`を8%混ぜた面 | 同左 |
| `--danger` | 取り消せない操作 | `#a33a2a` | `#e08472` |
| `--danger-wash` | 危険なボタンに触れたときの面 | `--danger`を12%混ぜた透明 | 同左 |
| `--ok` | 準備ができている・保存できた | `#2f7d4f` | `#6fbf8c` |
| `--warn` | 準備が足りない | `#93691c` | `#d9ad5a` |
| `--overlay` | ライトボックスの背後 | `rgba(0,0,0,0.8)` | 同左 |
| `--meter-track` | 音量メーターの溝 | `--muted`を35%混ぜた透明 | 同左 |

**罫線が2つある理由。**`--line` は飾りの区切り（カードの縁、節の下線）で、`--line-strong` は
押せるものの枠（ボタン・入力欄・カレンダーのマス・検索結果）である。WCAG（Web Content
Accessibility Guidelines。Webのアクセシビリティの国際的な指針）のAA水準は、
**操作できる部品の境界**に地との比`3対1`以上を求めるが、飾りの区切り線には求めない。
`--line` はこの比が`1.29`（明るい配色）しかないので、押せるものの枠だけを別の変数に分けた。

**生まれた出来事**：2026-09-15にコントラスト比を実測したところ、ボタンと入力欄の枠が
`1.29対1`で、AAの`3対1`を満たしていなかった。`--line` を濃くすると画面全体が箱だらけに
見えるので、押せるものの枠だけ `--line-strong` に分けた。

4px刻みの8段。

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--sp-1` | 4px | 行内の小さな隙間 |
| `--sp-2` | 8px | 部品どうしの既定の隙間 |
| `--sp-3` | 12px | カードの中の段落間 |
| `--sp-4` | 16px | カードの内側の余白、画面の左右の余白 |
| `--sp-5` | 20px | 設定の項目どうし |
| `--sp-6` | 24px | 設定の節どうし |
| `--sp-7` | 32px | 画面の節どうし |
| `--sp-8` | 48px | 画面の下の余白（2倍して使う） |

4px刻みに載らない半歩が4つある。**字のすぐ隣に置く小さな印と、既存の操作部品の内側の詰めに
だけ使う。新しい部品では使わない。**

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--sp-hair` | 2px | バッジの上下、マスの中の行間 |

| `--sp-wide` | 14px | ボタンの左右 |

**部品固有の寸法（サムネイルの64px、カレンダーのマスの最小高さ72pxなど）は直書きでよい。**
それは「間隔」ではなく、その部品にしか意味を持たない大きさだから。

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--radius-xs` | 4px | 記号ほどの小さな箱（キーの印、音量メーター） |
| `--radius-sm` | 6px | サムネイル |

### 3.5動き

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--dur-fast` | 120ms | 面の色の切り替え（ボタン・入口・マス・検索結果） |
| `--dur-meter` | 60ms | 音量メーターの追従。実際の音に遅れてはいけないので別枠 |

**トランジションは120msを超えない。**位置や大きさは動かさない——色だけを変える。
`prefers-reduced-motion: reduce`（動きを減らす設定）のときは、この2つを`1ms`にし、
アニメーションも1回・1msに切り詰める。

### 3.6幅

| 変数 | 値 | 意味 |
|---|---|---|
| `--body-width` | 42em | 本文の幅の上限。これ以上広げると1行が長くなって読み返しにくい |

**狭い画面の閾値は640px。**CSS変数はメディアクエリ（`@media`）の中で使えないので、
`@media (max-width: 640px)` と直接書く。根拠：復習の評価ボタン3つ（各10em＝160px）で480px、
これにボタン間の余白と画面左右の16pxを足すと640px。これ未満では横1列に入らない（05文書 §8.1）。

### 3.7フォーカス

| 変数 | 値 |
|---|---|
| `--focus` | `--accent`と同じ色 |
| `--focus-width` | 2px |
| `--focus-offset` | 1px |

キーボードで辿ったときだけ出す（`:focus-visible`）。マウスで押したときには出さない。
押せるものには例外なく付ける。

## 4. 部品

部品ごとに、役割／見た目の種類／状態／配置の規則／使ってはいけない例／CSSクラス名を書く。
**状態**は既定・ホバー（マウスを乗せた）・フォーカス（キーボードで辿り着いた）・無効・危険の5つを指す。

### 4.1ボタン

- **役割**：押すと何かが起きる操作。文は動詞で終える（§7）。
- **種類**：`primary`（塗りつぶし。画面に1つ）、既定（枠線）、`ghost`（枠線・地は透明。カードの中の副次的な操作）、`danger`（赤茶の枠線と文字。取り消せない操作）。
- **状態**：

| 状態 | 見た目 |
|---|---|
| 既定 | 面`--surface`、枠`--line-strong`、文字`--text` |
| ホバー | 面が`--hover-surface`に。`primary`は`--accent-hover`に |
| フォーカス | 2pxのアクセント色の枠が外側に1px離れて出る |
| 無効 | 文字`--muted`、枠`--line`、カーソルは`not-allowed`。**薄くしない** |
| 危険 | 地は透明、枠と文字が`--danger`。ホバーで`--danger-wash`が薄く敷かれる |

- **配置**：操作の並びは状態で増減させない（原則B）。主操作は右端（`.editor-actions`、`.form-actions`）。
- **使ってはいけない例**：
  - 塗りつぶしを2つ以上置く（原則F）。
  - 危険な操作を塗りつぶしにする（目立たせると押させたい操作に見える）。
  - 無効化を`opacity`でやる（薄いと「壊れている」「読み込み中」に見える）。
  - 使えないボタンを消す（押す位置が動く）。
- **クラス名**：`.button` ／ `.button.primary` ／ `.button.ghost` ／ `.button.danger`

**生まれた出来事**：05文書 §6で「無効化は `opacity` ではなく、文字色を `--muted`、枠を `--line` に
して、カーソルは既定のまま」と決めた。薄く見える無効化は「読み込み中」と見分けが付かないため。

### 4.2リンクをボタンの見た目で使うとき

- **役割**：押すと別の画面へ移る（URLが変わる）操作。「カレンダーへ」など。
- **見た目**：ボタンと同じ。下線を消し、中身を上下中央に置く（`a.button`）。
- **どちらを使うか**：URLが変わるなら`a`、その場で何かが起きるなら`button`。見た目が同じでも、
  `a`は新しいタブで開けるし、ブラウザの戻るが効く。
- **使ってはいけない例**：無効化したいのにリンクにする（`a`は`disabled`にできない。
  無効化が要るなら`button`にする。移動の帯の4つ目が、月の画面だけボタンなのはこれが理由）。
- **クラス名**：`a.button`

### 4.3上部の帯とナビ

- **役割**：アプリ名と、4つの入口（今日・カレンダー・検索・設定）を常に同じ順で出す。
- **見た目**：画面上部に貼り付く（`position: sticky`）。地は`--bg`、下に`--line`の1本。
- **状態**：現在地（`aria-current="page"`）は、面・枠・太字の3つで示す。色だけに頼らない（原則E）。
- **配置**：アプリ名が左、入口が右。**入口の数と並びは状態で変えない。**狭い画面（640px未満）では
  2段に分け、2段目に入口4つを等間隔で置く。
- **件数の印**：「今日」にだけ、まだ評価していない復習の件数を丸い印（`.nav-badge`）で添える。
  0件のときは印そのものを出さない（0を出すと「0件やれ」と読める）。
- **使ってはいけない例**：入口を状態で増やす・減らす・並べ替える。
- **クラス名**：`.topbar` ／ `.app-name` ／ `.topnav` ／ `.nav-badge`

### 4.4移動の帯（daybar）

- **役割**：月の画面と日の画面で、前後に移動し、元の場所へ戻る。**4つの部品を常にこの順で**置く：
  前へ（前の月／前の日）・見出し・次へ（次の月／次の日）・4つ目（今月へ／カレンダーへ）。
- **見た目**：`grid-template-areas` で配置を固定する。**折り返しに任せない。**
- **配置**：640px以上は1段（`prev title next jump`）。640px未満は必ず2段で、1段目が
  「前へ・見出し・次へ」、2段目が4つ目を全幅。この2通りだけを定義し、途中の割れ方は作らない。
- **使ってはいけない例**：`flex-wrap` で折り返させる。幅によって「3つ＋1つ」「2つ＋2つ」と
  割れ方が変わり、見出しの位置が動く。
- **クラス名**：`.daybar` ／ `.daybar-prev` ／ `.daybar-title` ／ `.daybar-next` ／ `.daybar-jump`

**生まれた出来事**：現行の帯は幅が足りないと折り返して見出しがずれた（2026-09-15の棚卸し）。
月と日で同じHTMLの構造・同じクラス名を使い、配置の規則を1つで済ませることにした。

### 4.5カード

- **役割**：1件のまとまり。記録カード、復習カード、文字起こし中のカード、設定の節。
- **見た目**：面`--surface`、枠`--line`（飾りなので細い方）、角丸`--radius`、内側`--sp-4`。
- **種類**：
  - **記録カード**（`.card`）：見出し → 状態1行 → サムネイル → 本文 → 操作ボタン4つ。
  - **復習カード**（`.card.review-card`）：開く前は手がかりだけ、開いた後は本文と評価3ボタン。
  - **文字起こし中**（`.card.transcribing`）：枠を破線にする。中身がまだ確定していないことを示す。
  - **設定の節**（`.settings-section`）：見出しの下に`--line`の1本を引く。
- **配置**：カードの中にカードを重ねない（原則A）。カードどうしは`--sp-4`で離す（`.cards`）。
- **使ってはいけない例**：復習を終えた記録のカード全体を薄くする。状態は状態1行の言葉で示す（原則E）。
- **クラス名**：`.cards` ／ `.card` ／ `.card-head` ／ `.card-title` ／ `.card-meta` ／ `.card-body` ／ `.card-actions` ／ `.transcribing` ／ `.review-card`

### 4.6状態1行（status-line）

- **役割**：その記録がいまどういう状態かを1行で述べる。「次の復習9月18日（金）・3日後・2回目」
  「復習は終了（9月10日に終了）」「復習しない記録」。
- **見た目**：補足の字（14px）、色`--muted`、数字は等幅。
- **配置**：カードの見出しのすぐ下。**空でも行を残さない**（内容が無いなら出さない）。
- **使ってはいけない例**：色で状態を示す（「終了」を灰色にするなど）。言葉で述べる（原則E）。
- **クラス名**：`.status-line`

### 4.7バッジ

- **役割**：短い印。記録カードの属性（画像の枚数など）。
- **見た目**：丸い枠（`--radius-pill`）、12px、色`--muted`、枠`--line`。`.subtle`は破線。
- **配置**：見出しの右（`.card-meta`）。
- **使ってはいけない例**：バッジの中に文をいれる。バッジは2〜6文字まで。
- **クラス名**：`.badge` ／ `.badge.subtle`

### 4.8入力欄

- **役割**：文字・数値を入れる。
- **並ぶ順は必ず「ラベル → 入力欄 → 一文の説明 → 詳しく」**。説明を入力欄の上に置かない
  （上に置くと、どの欄の説明か分からなくなる）。
- **見た目**：枠`--line-strong`、角丸`--radius`、内側`--pad-input`、行間は本文と同じ`1.7`。
- **状態**：フォーカスで2pxのアクセント枠。エラーはその場に赤字（`.field-error`）で
  「1〜200の範囲で指定してください」のように、正しい入れ方を書く。
- **配置**：件数や時刻のような短い数値は幅いっぱいに広げない（`.input-narrow`、最大8em）。
- **使ってはいけない例**：ラベルを補足の字（薄い灰色の小さな字）にする。設定画面では
  ラベルを16pxの太字にしてある。
- **クラス名**：`.field` ／ `.field-label` ／ `.input` ／ `.textarea` ／ `.field-help` ／ `.field-error` ／ `.input-narrow`

**生まれた出来事**：設定画面のラベルが入力欄より弱い字（`0.8rem`の`--muted`）で、
どの欄の説明なのか読み取りにくかった（2026-09-15）。設定の節の中だけラベルを強くした。

### 4.9チェック項目

- **役割**：オンとオフの2値。「復習の対象にする」「間隔が1年に達したら復習を終える」。
- **見た目**：チェックとラベルを1行に（`.field-checkbox-line`）、説明と注釈はその下。
  行全体が`label`なので、文字を押してもチェックが変わる。
- **使ってはいけない例**：オンとオフで文言を変える（「有効にする／無効にする」のように
  文が入れ替わると、いまどちらなのか分からなくなる）。文は固定し、チェックの有無で示す。
- **クラス名**：`.field-checkbox` ／ `.field-checkbox-line`

### 4.10注釈（「詳しく」）

- **役割**：一文の説明で足りないときに、畳んで置く追加の説明。`details`要素を使う。
- **中身は3点**：**目的**（何のための設定か）・**効果**（変えると何が起きるか）・**例**（具体的な値）。
  この3つを`dl`で、見出しの幅を`3em`に固定して並べる。
- **見た目**：畳んだ見出し（`summary`）はアクセント色。中身は補足の字。
- **使ってはいけない例**：`title`属性に説明を隠す（原則C）。畳んだ中に、読まないと操作できない
  情報を入れる（畳んでよいのは「知っていれば得をする」情報だけ）。
- **クラス名**：`.field-note`

### 4.11状態の箱（status-box）

- **役割**：読むだけの状態を、節の先頭に箱として出す。「文字起こしの準備：できています」
  「音声認識のプログラム（whisper-cli）が見つかりません」。
- **見た目**：枠`--line`、左だけ4pxの帯。帯の色は`.ok`で`--ok`、`.warn`で`--warn`。
- **配置**：節の見出しの直後。
- **使ってはいけない例**：帯の色だけで良し悪しを伝える。**必ず文で書く**（原則E）。
  できていないときは、直し方も箱の中に3行で書く。
- **クラス名**：`.status-box` ／ `.status-box.ok` ／ `.status-box.warn` ／ `.status-box-title`

### 4.12操作行（action-row）

- **役割**：ボタンと、その結果の文と、続きの操作（「Finderで開く」）を1行にまとめる。
- **見た目**：`grid`で桁を決める（`auto auto 1fr auto`、ボタンが1つなら`.action-row-single`で
  `auto 1fr auto`）。結果の文は伸び縮みする桁に置き、長いパスは折り返す。
- **配置**：640px未満では縦に積む。**並ぶ順は広い画面と同じ。**
- **使ってはいけない例**：`flex-wrap`で折り返させる（幅によって割れ方が変わる）。
- **クラス名**：`.action-row` ／ `.action-row-single` ／ `.action-result` ／ `.form-actions`

### 4.13一覧

3種類ある。共通の規則：**項目の数は変わってよい**（原則Bが禁じるのは操作部品の増減であって、
一覧の項目ではない）。押せる項目にはホバーとフォーカスを必ず付ける。

- **カレンダーのマス**（`.cal-grid` ／ `.cal-cell`）：月曜始まりの7列。マスは`a`要素。
  枠は`--line-strong`（押せるので）。今日のマスは`--accent`の2pxの枠。
  件数は0でも行の高さを残す（`.cal-count`に`min-height`）——数が変わっても高さが動かないように。
  月の外の空きマス（`.cal-blank`）は枠も地も透明。
- **検索結果**（`.hits` ／ `.hit`）：日付・見出し・抜粋・どこが一致したか。枠は`--line-strong`。
- **これからの復習**（`.upcoming`）：日ごとに`details`で畳む。今日から14日分。

### 4.14空・読み込み中・エラーの表示

| 状況 | 出し方 | クラス |
|---|---|---|
| 空 | 節の見出しは残し、その下に一文。「今日の復習はありません。次は9月17日（水）に2件あります。」 | `.empty` |
| 読み込み中 | 文で出す。「文字起こしの準備をしています…」。画面の骨組みは動かさない | `.pending`、`.transcribing` |
| エラー | 赤字の一文。原因と、次に何をすればよいかを書く。内部のキー名は出さない | `.error` |

**使ってはいけない例**：空のときに節ごと消す（次に来たときに場所が変わる。05文書 §3.1）。
読み込み中に回転する印だけを出す（何を待っているのか分からない）。

### 4.15確認ダイアログ

- **何を使うか**：ブラウザ標準の `confirm()` を使う。自前のダイアログは作らない。
- **理由**：（1）標準のダイアログはキーボードとスクリーンリーダーの扱いがブラウザ側で正しく
  実装済みで、フォーカスの閉じ込め・Escapeでの取り消し・読み上げを自前で作らずに済む。
  （2）画面の外側に出るので、押し間違いのその場から視線が外れて、いったん止まる。
  （3）利用者が1人のローカルアプリで、見た目をそろえる利益より、作らない利益が大きい。
- **文面の型**：**何が起きるか＋戻せるか＋よろしいですか**。
  例：「この記録を削除します。本文・画像・録音・復習の記録もすべて消え、元に戻せません。よろしいですか。」
- **同じ操作は、どの画面でも同じ確認文**にする（05文書 §5）。
- **使ってはいけない例**：「本当によろしいですか」だけ（何が起きるか書いていない）。
  戻せる操作に確認を出す（確認が多いと読まずに押すようになる）。

### 4.16ライトボックス

- **役割**：画像を画面いっぱいに拡大して見る。
- **見た目**：画面全体を`--overlay`（黒の80%）で覆い、中央に画像。カーソルは`zoom-out`。
- **操作**：どこを押しても閉じる。
- **クラス名**：`.lightbox`

### 4.17録音ボタン

- **役割**：録音を始める／止めて文字起こしに送る。
- **同じボタンが状態を変える。**「録音して記録する」を押すと、**同じ場所が**「停止して文字起こしする」に
  変わる。別のボタンが生えるのではない（原則B）。右に経過時間と音量メーターが出る。
- **状態**：待機・準備中・録音中・送信中の4つ。録音中は塗りつぶしになる
  （そのとき「止める」が画面で次にすべきことだから）。
- **画面ごとの既定**：復習カードが出ている「今日」画面では枠線。復習カードの無い日の画面では
  常に塗りつぶし（05文書 §6）。
- **場所を空けておく**：マイクの許可を求める案内（`.recorder-permission-hint`）は、
  出ても出なくても高さが動かないように最小の高さを確保してある。
- **クラス名**：`.recorder` ／ `.recorder-slot` ／ `.recorder-status` ／ `.recorder-meter` ／ `.recorder-meter-bar` ／ `.recorder-permission-hint`

## 5. パターン

部品の組み合わせ方。

### 5.1画面の骨格

**帯 → 見出し → 節**の順。

1. 上部の帯（全画面共通。アプリ名と4つの入口）
2. 画面の見出し（`.day-title`。日付や画面名）
3. 節（`.section`。見出し＋中身）を`--sp-7`（32px）ずつ離して並べる

### 5.2節は空でも見出しを残す

節の中身が0件でも、見出しは残し、その下に一文を置く。消すと、次に来たときに下の節の位置が
動いてしまう（原則B）。

### 5.3主操作の決め方

その画面で「いま次にすべきこと」を1つ選び、それだけを塗りつぶしにする。

| 画面 | いま次にすべきこと |
|---|---|
| 今日（復習が残っている） | 「思い出せたら開く」 |
| 今日（復習が0件・全部終えた） | 「録音して記録する」 |
| 日（`#/day/…`） | 「録音して記録する」（この画面に復習は出ない） |
| 設定 | 「保存」 |
| 復習カードを開いた後 | **無し**。評価3ボタンはどれも等しく正しい（原則F） |

### 5.4破壊的操作

区切り線の下に置き、`.button.danger`（赤茶の枠線）にし、押したら確認を出す。確認文には
「元に戻せません」を必ず入れる。似た名前の穏やかな操作があるときは、違いを注釈で常時出す。

例：「その他」メニューの最下部に区切り線（`.more-menu-sep`）を挟んで「この記録を削除する」を置き、
その直下に「「もう復習しない」と違い、記録そのものが消えます。」を常時出す。

### 5.5状態で部品を消さない

押せないときは無効化して、その場に残す。無効化は`opacity`ではなく、文字を`--muted`、
枠を`--line`にする。

### 5.6数値と日付の書き方

画面に出す形は「**9月18日（金）・3日後・2回目**」。年は同じ年なら省く。曜日は必ず付ける。
「何日後か」は必ず添える（日付だけだと近いのか遠いのか分からない）。内部の名前
（stability、reps、lapsesなど）は画面に出さない（05文書 §4の表）。

### 5.7確定と予告を言い分ける

| 種類 | 言い方 | 出る場所 |
|---|---|---|
| 確定（もう決まっている） | 「次の復習9月18日（金）・3日後」 | 記録カードの状態1行 |
| 予告（このボタンを押したらこうなる） | 「次回：9月22日（火）・6日後」 | 復習の評価ボタンの中 |

同じ文字列を両方に使わない。

**生まれた出来事**：現行は確定と予告がどちらも「次回 …」で、評価前の予告なのか評価後の
確定なのか読み分けられなかった（2026-09-15の棚卸し）。

### 5.8狭い画面の規則

**横1列は縦1列にだけ変える。途中で「2つ＋1つ」に割れる配置を作らない。**割れ方が幅で変わると、
見出しの位置が動く。閾値は640px（§3.6）。

| 部品 | 640px以上 | 640px未満 |
|---|---|---|
| 復習の評価ボタン | 横3列 | 縦1列 |
| 移動の帯 | 1段（4つ横並び） | 2段（3つ＋全幅1つ）に**固定** |
| 上部の帯 | 1段 | 2段（アプリ名／入口4つ） |
| 設定の操作行 | 横並び | 縦積み（順は同じ） |
| カレンダーのマス | 7列 | 7列のまま小さくする |

**狭い画面の規則は `styles.css` の最後に書く。**同じ強さの規則はあとに書いた方が勝つので、
部品の定義より前に置くと打ち消される。

**生まれた出来事**：2026-09-15に、狭い画面の規則をファイルの途中に置いたところ、あとに書いた
`.cal-count` の定義に上書きされ、幅400pxでカレンダーのマスの件数が縮まずに2行に折り返した。

## 6. アクセシビリティ

利用者は1人だが、その1人が疲れている・画面が眩しい・マウスが無い、という日がある。

### 6.1キーボード操作

- すべての操作がキーボードだけで届く。押せるものは`button`か`a`で作る（`div`に`onClick`を付けない）。
- 復習カード：SpaceまたはEnterで「開く」、`1`・`2`・`3` で評価。
- **日本語IMEの変換中はキー操作を無視する**（要件J5）。`web/src/hooks/ime.ts` の `useIme` を使う。
  変換中の`1`を評価だと解釈すると、文章を打っている途中で復習が進んでしまう。
- 入力欄にフォーカスがあるときは、上の1文字キーを効かせない。

### 6.2フォーカスの可視

押せるものすべてに`:focus-visible`で2pxのアクセント色の枠を出す（§3.7）。
`outline: none` を書かない。マウスで押したときには出さない（`:focus`ではなく`:focus-visible`）。

### 6.3現在地の伝え方

上部の帯の現在の入口に`aria-current="page"`を付ける。見た目（面・枠・太字）と、
支援技術に読ませる印の両方を出す。

### 6.4ダイアログ

ブラウザ標準の`confirm()`だけを使う（§4.15）。自前のダイアログを作らない。

### 6.5色だけに頼らない

状態は言葉で書き、色は補助（原則E）。良し悪しを示す箱には必ず文がある。件数の印には数字がある。
現在地は色に加えて面・枠・太字で示す。

### 6.6コントラスト

WCAG 2.2のAA水準を満たす。本文は`4.5対1`以上、大きな文字と操作できる部品の境界は`3対1`以上。
実測値は§3.1の表。**色を変えたら、この表を測り直して更新する。**

### 6.7拡大

ブラウザの拡大200%で崩れない。そのために：大きさはできるだけ`rem`と`em`で書く
（本文幅`42em`、入力欄の最大幅`8em`）。固定の高さを付けない。文字が増えたら箱が伸びるようにする。

### 6.8OSの設定に従う

- `prefers-color-scheme`：明るい配色と暗い配色を切り替える。アプリ内の切り替えは作らない。
- `prefers-reduced-motion`：トランジションとアニメーションを切る（§3.5）。

## 7. 執筆（画面に出る言葉）

置き換え表と正書法は05文書 §5にある。ここでは**部品ごとの文の型**だけを決める。

| 部品 | 型 | 例 | だめな例 |
|---|---|---|---|
| ボタン | 動詞で終える | 「録音して記録する」「控えを作る」 | 「録音」「控え」 |
| 主操作のボタン | 動詞＋その結果 | 「思い出せたら開く」 | 「開く」 |
| 確認文 | 何が起きるか＋戻せるか＋よろしいですか | 「この記録を削除します。本文・画像・録音・復習の記録もすべて消え、元に戻せません。よろしいですか。」 | 「本当によろしいですか」 |
| 設定の説明 | 変えると何が起きるか | 「期限が来た記録がこの件数を超えた日は、超えた分を翌日以降に回します。」 | 「1日の復習の上限です」 |
| 状態の箱 | 状態＋（できていないなら）直し方 | 「文字起こしの準備：できています」 | 「OK」 |
| 空の表示 | 事実＋次に何が起きるか | 「今日の復習はありません。次は9月17日（水）に2件あります。」 | 「該当なし」 |
| エラー | 何が起きたか＋どうすればよいか | 「1〜200の範囲で指定してください」 | 「Validation error（daily_review_limit）」 |

**画面に出す文字列は `web/src/i18n/ja.ts` にだけ書く。**TSXに直書きしない。

**正書法**（和文と半角英数の間を詰める、機能する記号は全角、三点リーダーは`…`）は
`mise run check:text` が検査する。この文書を含む `docs/**/*.md` も検査の対象で、
Edit・Writeのあとにフックが自動で走る。

## 8. 運用

### 8.1部品を足す・変えるときの手順

1. **既にある部品で足りないか確かめる。**足りるなら足さない。
2. **トークンだけを使う。**色・間隔・字の大きさ・角丸・時間を直書きしない。必要な値が無いときは、
   部品の中に書くのではなく§3にトークンを足す。
3. **5つの状態を定義する。**既定・ホバー・フォーカス・無効・危険。要らない状態は「無し」と書く。
4. **ホバーとフォーカスを必ず付ける。**押せるのに反応しない部品を作らない。
5. **配置を固定する。**主要な部品を`flex-wrap`で折り返させない。狭い画面の変化は
   「横1列→縦1列」だけ。
6. **幅400pxと1000px、明るい配色と暗い配色の4通りで見る。**`mise run verify` でポート8798に
   検証用サーバーを立て、CDP（Chrome DevTools Protocol）で撮る。撮影は`shots/`に残す。
7. **この文書に節を足す。**§4か§5に、役割・状態・配置・使ってはいけない例・クラス名を書く。
   規則には、それが生まれた出来事を1つ添える。
8. `mise run check`（型検査・単体テスト・正書法・ビルド）を通す。

### 8.2確認リスト

部品を足した・変えたら、次の8つを確かめる。

1. 直書きの色・px・フォントサイズが無い（部品固有の寸法は除く）。
2. ホバーとフォーカス（`:focus-visible`）が付いている。
3. 無効化が`opacity`ではなく色で、部品はその場に残る。
4. 状態が言葉で書かれていて、色は補助になっている。
5. 幅400pxで、横並びが「2つ＋1つ」に割れていない。
6. 明るい配色と暗い配色の両方で、文字が地から`4.5対1`以上離れている。
7. 説明が平文で置かれていて、`title`属性に隠れていない。
8. CSS規則の無いクラス名を新しく作っていない。

### 8.3禁止事項

| 禁じること | 理由 |
|---|---|
| インラインスタイル（`style=`属性） | 規則が1か所にまとまらなくなる。例外は、値が実行時にしか決まらない場合（音量メーターの幅、隠しファイル入力の`display: none`）だけ |
| `opacity`での無効化 | 薄い部品は「読み込み中」「壊れている」と見分けが付かない |
| `title`属性だけの説明 | マウスを乗せないと読めない。タッチでは読めない |
| 主要な部品を`flex-wrap`で折り返す | 幅によって割れ方が変わり、位置が動く。`grid-template-areas`で2通りだけ定義する |
| CSS規則の無いクラス | 何のための名前か誰にも分からなくなる。棚卸しで7つ見つかった |
| `box-shadow` | 奥行きは面と罫線だけで表す（原則A） |
| `outline: none` | キーボードで辿れなくなる |
| 新しい色の追加 | §3.1の表にある色だけを使う。足すときはこの文書を先に直す |

## 9. クラス名の改名候補

`web/src/*.tsx` は別の担当が編集中のため、今回は名前を変えていない。あとでまとめて直すときの候補を、
理由とともに残す。**変えるときは、この文書の§4のクラス名も同時に直すこと。**

| いまの名前 | 候補 | 理由 |
|---|---|---|
| `.more` ／ `.more-menu` | `.entry-more` ／ `.entry-more-menu` | 「その他」が何の「その他」か分からない。記録カード専用の部品である |
| `.more-menu-sep` | `.entry-more-divider` | `sep`が略語。区切り線であることが読めない |
| `.hit` ／ `.hits` | `.search-result` ／ `.search-results` | `hit`は検索の内部語。画面では「検索結果」と呼んでいる |
| `.status-line` | `.schedule-line` | 「復習の予定の1行」であって、汎用の状態表示ではない。`.status-box`と`.settings-status`も別物なのに`status`で衝突している |
| `.status-box` | `.notice-box` | 読むだけの知らせの箱。`status`を3か所で別の意味に使わない |
| `.settings-status` | `.save-status` | 「保存しました」の表示。設定画面の状態一般ではない |
| `.nav-badge` | `.count-badge` | `.badge`（カードの印）と役割が違う。こちらは件数の数字 |
| `.daybar` | `.stepbar` | 日だけでなく月の画面でも使う。「1つ前・1つ次へ動く帯」の意味 |
| `.thumb-img` ／ `.thumb` | `.thumb-small` ／ `.thumb-editable` | 前者はカードの中の小さい表示、後者は編集中の削除ボタン付き。名前から区別が付かない |
| `.recorder-slot` ／ `.capture-slots` | `.recorder-row` ／ `.capture-row` | `slot`が何を指すのか分からない。どちらも横1行の入れ物 |
| `.action-row-single` | `.action-row-3col` | 「単一」が何の単一か分からない。実体は桁数が4から3に減る指定 |
| `.transcribing` | `.card-transcribing` | `.card`と一緒にしか使わないので、単独で現れると何のことか分からない |
| `.empty` | `.empty-state` | `.empty`は「空である」という状態名に見えるが、実体は「空のときに出す表示」 |
| `.field-note` | `.field-detail` | 中身は畳んだ「詳しく」。`note`だと常時出る注記に読める |
| `.kv` ／ `.pending` | （削除候補） | どちらも現在どのTSXからも使われていない。使われないまま残すと、次に読む人が探す |

## 10. していないこと

- **Safariでの確認をしていない。**撮影と確認はChromeだけで行った。
- **拡大200%の確認を、実際のブラウザでしていない。**固定の高さを使わない方針をCSSで守っただけで、
  200%にして目で見てはいない。
- **スクリーンリーダーでの読み上げを確認していない。**`aria-current`を付けた事実があるだけで、
  実際に読み上げさせていない。
- **印刷の見た目を決めていない。**`@media print`は書いていない。
- **`.kv`と`.pending`を消していない。**使われていないが、TSXを別の担当が編集中なので、
  あとで使う可能性を排除できなかった（§9に削除候補として挙げた）。
